# Bloodraven Alert & Event Runbook Matrix

Quick lookup matrix mapping Prometheus alerts and Kubernetes Events to root causes and verified remediation commands.

| Alert / Event | Impact & Severity | Key Diagnostic Checks | Recommended Remediation Action |
|---|---|---|---|
| `PITRArchiveNotFound` / `PITRArchiveLegacy` / `PITRArchiveDescriptorMissing` / `PITRArchiveIdentityMismatch` / `PITRArchiveEncryptionMismatch` / `PITRArchiveKeyMismatch` / `PITRArchiveVersionUnsupported` / `PITRArchiveObjectInvalid` / `PITRArchiveHistoryReset` / `PITRArchiveListFailed` (restore or verification) | 🟠 **HIGH** (The archive the restore reads was refused before replay) | Status message (token, archive ID, destination); `archiveProfileName`; the descriptor `<prefix>/binlogs/archive.json` (plaintext); the backup's `status.pitrArchiveID` | Wrong profile (`NotFound`); pre-v1.7.0 prefix needs a pre-v1.7.0 image (`Legacy`); wait for replication or restore `archive.json` (`DescriptorMissing`); the backup belongs to another archive (`IdentityMismatch`); fix encryption or passphrase (`EncryptionMismatch` / `KeyMismatch`); a newer format needs the release that wrote it, but a message saying `archive.json is damaged` needs the original object restored (bucket versioning, a copy) or a new prefix (`VersionUnsupported`); `ListFailed` is only a listing refused for permission and names its cause: S3 403 → grant `s3:ListBucket`, PVC permission error → make the archive volume readable by the Job's user (other listing or manifest read failures are retried and, if they persist, fail without a token; a row "retired" during planning is transient: retry); on a replicated copy, any refusal that names a missing or unreadable object can be replication lag: check the copy is complete before applying a permanent remedy; a reset epoch needs a new prefix plus full backup (`HistoryReset`). See playbook 32. |
| `PITRArchiveDestinationShared` / `PITRTargetInvalid` / `PITRBackupFiltered` / `PITRBackupAfterTarget` (`RestoreBuildFailed`) | 🟠 **HIGH** (Restore not started) | `initFromBackup.pointInTime` (`archiveProfileName`, `stopTime`), `loadOptions.includeSchemas`/`excludeSchemas`, the backup's `completionTime` | Keep `spec.backup.pitr` on its own prefix. A fix inside `spec.initFromBackup` (the target `stopTime`: RFC 3339, an explicit zone, whole seconds; the load filters; an earlier backup or a later target) cannot be an edit: the block is fixed at creation, so delete the never-bootstrapped group and create it again with the corrected block ([A failed bootstrap restore](../../../../site/content/docs/7.backup-and-restore/2.backup-restore.md#a-failed-bootstrap-restore)). See playbook 32. |
| `PITRBackupIdentityUnknown` / `PITRBackupIdentityMismatch` / `PITRBackupInconsistent` / `PITRBackupIncomplete` (`dump-meta`) | 🟠 **HIGH** (The dump cannot be tied to its source and archive) | `dump-meta` termination message; the stamp `<location>.bloodraven-backup.json`; `MysqlBackup.status.failoverGroupUID`, `gtidExecuted` | Take a new full backup (pre-v1.7.0 dumps have no stamp); use the right `backupRef`. `IdentityUnknown` saying the dump `is encrypted … but the restore has no decryption passphrase`, `is not encrypted, but the restore decrypts this dump` or `does not decrypt with the configured passphrase` is the restore source's encryption setting: fix it rather than take a new backup. `larger than its bound`: a stamp over 1 MiB or an `@.json`/`@.done.json` over 16 MiB, i.e. a replaced object. A `dump-meta` failure without a token is a transient store error that persisted through its retries. See playbook 32. |
| `PITRTargetNotCovered` / `PITRStopAmbiguous` / `PITRBackupNotOnLineage` / `PITRExcludeIntersectsBackup` / `PITRNoArchivedReplay` / `PITRPlanTooLarge` / `PITRReplayUnsupported` | 🟠 **HIGH** (Requested recovery or verification refused) | Refusal message (it names the target, sets and safe targets); `pitr-download` log `pitr plan` / `download site binlogs` | Flush and wait for archiving (`TargetNotCovered`, `NoArchivedReplay`); choose a target the message offers or exclude the named errant (`StopAmbiguous`); use a backup on the target history (`NotOnLineage`, `ExcludeIntersectsBackup`); `PlanTooLarge`: the message names the limit hit: Job memory (raise the memory limit; for the event-size bound only below its 64 MiB cap, at the cap pick a target whose plan does not read that file), the staging volume (raise `spec.backup.stagingVolumeSizeLimit`) or the node's free ephemeral storage (schedule the Job on a node with more), or use a backup closer to the target; avoid XA in the window (`ReplayUnsupported`). See playbook 32. |
| `PITRArchiveDivergentHistory` / `PITRArchiveSplitBrain` / `PITRArchiveGap` / `PITRArchiveOrderConflict` / `PITRArchiveOrderInversion` / `PITRArchiveNamespaceReuse` | 🟠 **HIGH** (The archive does not prove one history from the backup to the target) | Refusal message and `BLOODRAVEN_PITR_DIVERGENT_SET`; recent failovers; `gtid-audit.sh` divergent rows and promotion records | Copy the printed set into `excludeGtids` when it is history to drop, or use a later backup / earlier target; for gaps and inversions follow the message; reuse needs a new prefix plus full backup. See playbook 42. |
| `PITRCoverageInvalid` / `PITRReplayMismatch` / `PITRReplayFailed` (`restore.py`; the termination message starts `BLOODRAVEN_PITR_FAILED: ...`) | 🟠 **HIGH** (Replay checks or the replay itself failed) | Main container termination message and log (`BLOODRAVEN_PITR_SEGMENT k=`); Job rendered by which operator version | Retry with matching operator versions; preserve `coverage.json` for `ReplayMismatch`; empty a loaded bootstrap target before retrying. | `PITRDivergentHistoryExcluded` / `PITROnHistoryTransactionsExcluded` Warning | 🟡 **MEDIUM** (Restore or verification succeeded with exclusions) | `pointInTime.excludedDivergentTransactionCount`, `onHistoryExclusions` | Confirm the excluded set is what you meant to drop; on-history exclusions are not certified, so check the affected rows. See playbook 42. |

| `PITRArchiveTailNotArchived` Warning / operator WARN `pre-reclone archive tail not archived` | 🟡 **MEDIUM** (A reclone wiped a site's binary logs before its tail was confirmed archived; restore windows that need transactions only that tail held refuse `PITRArchiveGap`.
