Next steps:
  1. Install external-dns with the DNSEndpoint CRD source enabled for your DNS provider.
  2. Create a Secret with MySQL credentials (ROOT_PASSWORD, REPLICATION_USER, etc.)
  3. Create a MysqlFailoverGroup custom resource:

     kubectl apply -f - <<EOF
     apiVersion: shipstream.io/v1alpha1
     kind: MysqlFailoverGroup
     metadata:
       name: orders
       namespace: {{ .Release.Namespace }}
     spec:
       secretName: mysql-credentials
       sidecarImage: ghcr.io/shipstream/bloodraven-sidecar:{{ .Chart.AppVersion }}
       dns:
         hostname: orders.az.example.com
         ttl: 60
       sites:
         - name: iad
           zone: us-east-1a
           lbIP: 10.0.1.1
           storage:
             size: 50Gi
             storageClassName: fast-ssd
         - name: pdx
           zone: us-west-2a
           lbIP: 10.0.2.1
           storage:
             size: 50Gi
             storageClassName: fast-ssd
     EOF

  3. Monitor the operator:
     kubectl logs -f deploy/{{ include "bloodraven.fullname" . }} -n {{ .Release.Namespace }}

  4. Check the failover group status:
     kubectl get mysqlfailovergroups -n {{ .Release.Namespace }}

  5. (ArgoCD users) Register custom health checks so MysqlFailoverGroup and
     MysqlBackup resources show proper health in the ArgoCD UI.

     Extract the patch file from the chart and apply it:
       helm pull bloodraven/bloodraven --untar
       kubectl patch configmap argocd-cm -n argocd \
         --patch-file bloodraven/argocd/argocd-cm-patch.yaml

     See https://bloodraven.readthedocs.io/en/latest/docs/getting-started#argocd-integration
