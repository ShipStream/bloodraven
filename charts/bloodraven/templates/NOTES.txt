Next steps:
  1. Install external-dns with the DNSEndpoint CRD source enabled for your DNS provider.
  2. Create the operator credentials Secret (keys username, password,
     MYSQL_ROOT_PASSWORD; optionally MYSQL_REPLICATION_USER and
     MYSQL_REPLICATION_PASSWORD), e.g.:

     kubectl create secret generic orders-mysql-operator -n {{ .Release.Namespace }} \
       --from-literal=username=bloodraven \
       --from-literal=password=<operator-password> \
       --from-literal=MYSQL_ROOT_PASSWORD=<root-password>

  3. Create a MysqlFailoverGroup custom resource:

     kubectl apply -f - <<EOF
     apiVersion: shipstream.io/v1alpha1
     kind: MysqlFailoverGroup
     metadata:
       name: orders
       namespace: {{ .Release.Namespace }}
     spec:
       credentials:
         operatorSecretName: orders-mysql-operator
       dns:
         hostname: orders.az.example.com
         ttlSeconds: 60
       sites:
         - name: iad
           serverID: 101
           zone: us-east-1a
           taintNodeSelector:
             bloodraven.shipstream.io/failover-group.orders: "true"
             bloodraven.shipstream.io/site.orders: iad
           loadBalancerIP: 10.0.1.1
           storage:
             size: 50Gi
             storageClassName: fast-ssd
         - name: pdx
           serverID: 102
           zone: us-west-2a
           taintNodeSelector:
             bloodraven.shipstream.io/failover-group.orders: "true"
             bloodraven.shipstream.io/site.orders: pdx
           loadBalancerIP: 10.0.2.1
           storage:
             size: 50Gi
             storageClassName: fast-ssd
     EOF

     Groups that leave spec.sidecar.image empty run the sidecar this release
     ships with: {{ include "bloodraven.sidecarImage" . }}

  4. Monitor the operator:
     kubectl logs -f deploy/{{ include "bloodraven.fullname" . }} -n {{ .Release.Namespace }}

  5. Check the failover group status:
     kubectl get mysqlfailovergroups -n {{ .Release.Namespace }}

  5. (ArgoCD users) Register custom health checks so MysqlFailoverGroup and
     MysqlBackup resources show proper health in the ArgoCD UI.

     Extract the patch file from the chart and apply it:
       helm pull bloodraven/bloodraven --untar
       kubectl patch configmap argocd-cm -n argocd \
         --patch-file bloodraven/argocd/argocd-cm-patch.yaml

     See https://bloodraven.dev/docs/operations/gitops#argo-cd-health-checks
