This page lists the annotation keys that act as API, with who writes each one, the grammar of its value, and how stable it is:

- **Public**: you may set or read it, and it changes only with a release-noted break.
- **Operator-owned read-only**: the operator writes it; you may read it, but do not edit it.
- **Internal (may change)**: operator bookkeeping. Do not read or edit it; its key and value can change in any release.

One-shot action annotations use one value grammar, `<subject>(:<key>=<value>)*`. A pair splits at its first `=`, and a value matches `^[A-Za-z0-9._/+-]+$`, so it never contains `:` or `=`. An instant inside a value uses the ISO 8601 basic UTC form, for example `20261104T100000Z`. A structured internal value is a JSON object with a `schemaVersion` member; the operator ignores a payload with a version it does not know. Never commit an action annotation to a GitOps repository: a sync re-applies it.

So far this page covers the planned-failover keys. The remaining keys are described in the [CRD reference](/docs/configuration/crd-reference#annotations) until this page lists every key.

## Planned failover

All keys are on the `MysqlFailoverGroup`. See [Planned failover](/docs/operations/planned-failover).

| Key | Writer | Value | Stability |
|---|---|---|---|
| `bloodraven.shipstream.io/planned-failover` | User (`kubectl bloodraven promote`) | `<site>[:maxLagWait=<duration>]`. The operator removes it when the run is accepted, or keeps it while the run is `Deferred`. | Public |
| `bloodraven.shipstream.io/acknowledge-planned-failover-hold` | User (`kubectl bloodraven ack-planned-failover-hold`) | `<runID>`, the held run's `status.plannedFailoverHold.runID`. An operator-minted run id cannot match another group, so the value needs no `confirm=` or `uid=` pair. The operator removes it after it clears the hold. | Public |
| `bloodraven.shipstream.io/promotion-gtid-executed` | Operator | The promotion watermark (a GTID set), the out-of-band copy of `status.promotionGtidExecuted`, written with `last-failover` and `last-failover-target`. Omitted above 64 KiB. Ignored unless `promotion-gtid-executed-for` names the event the other two keys record. | Operator-owned read-only |
| `bloodraven.shipstream.io/promotion-gtid-executed-for` | Operator | `<RFC3339 last-failover> <last-failover-target>`, for example `2026-11-04T10:00:00Z iad`: binds the watermark to its failover event. Written and deleted in the same patch as `promotion-gtid-executed`. | Operator-owned read-only |
| `bloodraven.shipstream.io/planned-failover-terminal` | Operator | `{"schemaVersion":1,"runID":"<runID>","outcome":"<outcome>","reason":"<reason>","warnings":["<warning>"]}` (`reason` and `warnings` may be omitted; `warnings` are the run's terminal warning tokens). Ends a run whose status writes stalled; a `ManualRecoveryRequired` marker is also a hold record. | Internal (may change) |
| `bloodraven.shipstream.io/planned-failover-stall-since` | Operator | `<runID>:since=<YYYYMMDDThhmmssZ>`, the durable start of the status-stall deadline. | Internal (may change) |
| `bloodraven.shipstream.io/planned-failover-manager-absent-since` | Operator | `<runID>:since=<YYYYMMDDThhmmssZ>`, the durable start of the manager-absence deadline. | Internal (may change) |
| `bloodraven.shipstream.io/planned-failover-confirmed` | Operator | `<runID>:since=<YYYYMMDDThhmmssZ>`, the time the run's promotion was confirmed; written before the confirmed run releases its claim, removed when the run ends. | Internal (may change) |
| `bloodraven.shipstream.io/planned-failover-status-fence` | Operator | An ISO 8601 basic UTC instant with nanoseconds (`20261104T100000.123456789Z`), bumped to prove that an ambiguous status write can never commit. Each bump moves past the stored value. | Internal (may change) |
