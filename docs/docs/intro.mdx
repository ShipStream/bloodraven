# Bloodraven

Bloodraven is a Kubernetes operator for managing MySQL async replication failover groups across two sites. It automates failover detection, promotion, DNS steering, and application workload migration so that a site-level MySQL outage is resolved without human intervention.

## What it does

- **Monitors** two MySQL instances (one per site) via a 2-second polling loop with configurable failure and recovery thresholds
- **Detects** when the active primary becomes unreachable and **promotes** the standby replica to primary
- **Steers traffic** by updating a DNSEndpoint CR (consumed by external-dns) to point to the new primary's load balancer IP
- **Migrates workloads** by tainting nodes at the failed site so Kubernetes evicts application pods
- **Prevents split-brain** with sidecar self-fencing: if both the operator and peer are unreachable, the sidecar sets `super_read_only=ON` as a safety net
- **Broadcasts status** over a WebSocket API for dashboards and alerting integrations

## Components

| Component | Description |
|---|---|
| `bloodraven` | The operator binary. Runs as a Deployment, watches `MysqlFailoverGroup` CRs, reconciles MySQL state. |
| `bloodraven-sidecar` | Runs alongside each MySQL container. Provides health probes and self-fencing when the operator is unreachable. |

## Custom Resource

Bloodraven introduces a single CRD:

- **`MysqlFailoverGroup`** (`shipstream.io/v1alpha1`) -- Declares a pair of MySQL instances across two named sites, their storage, networking, DNS, TLS, and failover tuning.

```yaml
apiVersion: shipstream.io/v1alpha1
kind: MysqlFailoverGroup
metadata:
  name: orders
spec:
  secretName: mysql-credentials
  dns:
    hostname: orders.az.example.com
    ttl: 60
  sites:
    - name: iad
      zone: us-east-1a
      lbIP: 10.0.1.1
      storage:
        size: 50Gi
        storageClassName: gp3
    - name: pdx
      zone: us-west-2a
      lbIP: 10.0.2.1
      storage:
        size: 50Gi
        storageClassName: gp3
```
