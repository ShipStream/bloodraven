# How to upgrade from 0.9 to 1.0

Move a running Bloodraven install from 0.9.0 or 0.9.1 to 1.0.0. MySQL stays
on `mysql:9.7`; this is an operator, CRD, and sidecar bump.

## What changes

| Area | 0.9.x | 1.0.0 |
|---|---|---|
| Operator / sidecar images | `0.9.0` or `0.9.1` | `1.0.0` |
| Helm chart | `0.9.0` or `0.9.1` | `1.0.0` |
| License | none in-tree | [Business Source License 1.1](./licensing.mdx) |
| `spec.connectionDrainTimeout` | absent | new, default `30s` |
| `spec.updateStrategy` | accepted, ignored | honored |

The CRD change is additive. Existing failover groups keep working without
edits. After promotion, the operator now retries application-session eviction
on a fenced former primary for up to `connectionDrainTimeout`.

`updateStrategy` was a no-op in 0.9.x. In 1.0.0, `Recreate` restarts every
site at once. Leave the default `OrderedUpdate` unless you intend that.

If you use `spec.encryptionAtRest`, 1.0.0 stops replicating master-key
rotation and can recover a sealed site after the escrow Secret is restored.
Do not reclone an encrypted site on 1.0.0: that path can livelock (issue
[#144](https://github.com/ShipStream/bloodraven/issues/144)). See
[Data-at-rest encryption](./encryption-at-rest.mdx).

Production use by a company over $1M annual revenue now requires a
commercial license. Dev, test, staging, and smaller companies stay free.
See [Licensing and pricing](./licensing.mdx).

## Before you start

- One writable primary, healthy replicas, and no failover in progress.
- A recent backup you have [verified](./backup-verification.mdx).
- `spec.updateStrategy: OrderedUpdate` on each group, or omit the field.

## Upgrade

1. Apply the 1.0.0 CRDs. Helm does not upgrade files in `crds/`.

   ```bash
   kubectl apply -f https://raw.githubusercontent.com/ShipStream/bloodraven/v1.0.0/config/crd/bases/shipstream.io_mysqlfailovergroups.yaml
   kubectl apply -f https://raw.githubusercontent.com/ShipStream/bloodraven/v1.0.0/config/crd/bases/shipstream.io_mysqlbackups.yaml
   kubectl apply -f https://raw.githubusercontent.com/ShipStream/bloodraven/v1.0.0/config/crd/bases/shipstream.io_mysqlbackupverifications.yaml
   kubectl apply -f https://raw.githubusercontent.com/ShipStream/bloodraven/v1.0.0/config/crd/bases/shipstream.io_mysqldatabases.yaml
   kubectl apply -f https://raw.githubusercontent.com/ShipStream/bloodraven/v1.0.0/config/crd/bases/shipstream.io_mysqlstandbyclusters.yaml
   ```

2. Upgrade the operator.

   ```bash
   helm repo add bloodraven https://raw.githubusercontent.com/ShipStream/bloodraven/gh-pages
   helm repo update
   helm upgrade bloodraven bloodraven/bloodraven \
     --namespace bloodraven \
     --version 1.0.0 \
     --reuse-values \
     --set image.tag=1.0.0
   kubectl -n bloodraven rollout status deploy/bloodraven
   ```

   OCI equivalent: `helm upgrade bloodraven oci://ghcr.io/shipstream/bloodraven/helm/bloodraven --version 1.0.0`.
   GitOps: bump the chart `targetRevision` after the CRD app has synced.

3. Pin each failover group to the 1.0.0 sidecar. 0.9.0's CRD default was
   `0.1.6`; do not leave that implicit.

   ```bash
   kubectl -n orders patch mysqlfailovergroup orders --type merge -p '{
     "spec": {
       "sidecarImage": "ghcr.io/shipstream/bloodraven-sidecar:1.0.0",
       "updateStrategy": "OrderedUpdate"
     }
   }'
   ```

   `OrderedUpdate` rolls the standby first, then fails over, then rolls the
   old active. See [Ordered updates](./failover.mdx#ordered-updates).

4. Confirm the operator image, sidecar pin, and group health:

   ```bash
   kubectl -n bloodraven get deploy bloodraven -o jsonpath='{.spec.template.spec.containers[0].image}{"\n"}'
   kubectl -n orders get mysqlfailovergroup orders -o jsonpath='{.spec.sidecarImage}{"\n"}'
   kubectl -n orders get mysqlfailovergroup orders -o wide
   ```

   You want `ghcr.io/shipstream/bloodraven:1.0.0`, sidecar `…:1.0.0`, one
   writable site, and replicas `Ready`.

## After the upgrade

- Sidecar and operator versions must match once the rollout finishes. 0.9.x
  sidecars under a 1.0.0 operator are outside the
  [one-minor skew window](./upgrade-policy.mdx#sidecar--operator-skew).
- Optional: rebuild `kubectl-bloodraven` with
  `make install-kubectl-plugin KUBECTL_PLUGIN_VERSION=v1.0.0`.
- Do not change `spec.image` as part of this upgrade. MySQL stays `mysql:9.7`.
